Find.ly serves its own modules. Most are powered by our search provider, **Intelligence X** (the `intelligence-search`, `phonebook`, `identity-portal`, `system-id` and `storage-id` modules, plus Stealer Export); **`breach-search` is ours** — it runs on a breach index Find.ly ingests and documents itself, on its own separate quota.

Every search is a `POST` with a JSON object body:

```text
POST https://findly.icu/api/v1/search/{module}
```

| `{module}` | What it returns | Body fields | `?format=txt` |
| --- | --- | --- | --- |
| `intelligence-search` | Records matching free text | `query`, `max_results`, `media_type`, `sort_order`, `date_from`, `date_to` | No |
| `phonebook` | Emails, subdomains or URLs for a domain | `type`, `query` | Yes: one selector per line |
| `identity-portal` | Records for an email, domain or selector | `query` | No |
| `system-id` | A raw file, by its System ID | `system_id` | Yes: the file |
| `storage-id` | A raw file, by storage ID and bucket | `storage_id`, `bucket` | Yes: the file |
| `breach-search` | A person's records across our own breach index | `query`, `fields` | No |

Professional and Enterprise include every search module (and Stealer Export, below). An unknown slug returns `404 unknown_module`.

<Note>
  **`breach-search` draws from its own daily bucket**, not the IntelX request quota — see
  [Billing and quotas](/guides/billing-and-quotas#daily-quotas). Its `usage` block therefore reports the Breach Search
  bucket, so `daily_quota` differs from the other modules on the same key.
</Note>

<Note>
  **Stealer Export is not a search module.** It returns a `.zip` archive instead of JSON, so it has its own
  address — `POST /api/v1/stealer-export` — and its own page: [Stealer Export](/guides/stealer-export).
  Calling `/api/v1/search/stealer-export` returns `400 not_a_search_module`.
</Note>

## Rules that apply to every body

- The body must be a JSON object of **16 KB or less** (`400 invalid_json`, `413 body_too_large`). `Content-Type: application/json` is recommended but not required.
- **Unknown fields are rejected** with `422 invalid_input`, so a typo such as `systemId` is reported instead of ignored.
- Values are **strings**. `max_results` also accepts a JSON number, and Breach Search's `fields` is an object of strings. `null` counts as absent.
- Leading and trailing spaces are trimmed. Text fields are limited to 200 characters (256 for Breach Search).
- Invalid input returns `422 invalid_input` with one message per field in `error.fields`, and is **never billed**.
- `GET` is not supported: a search value in a URL would end up in logs.

## IntelX Modules

Powered by our search provider, **Intelligence X**. Every search here draws **1 IntelX request**; so does Stealer Export, documented on [its own page](/guides/stealer-export).

### Intelligence Search

Free-text search by email, username, domain or keyword.

<ParamField body="query" type="string" required>
  Email, username, domain or text. 200 characters max.
</ParamField>
<ParamField body="max_results" type="number | string">
  Whole number from 1 to 1000.
</ParamField>
<ParamField body="media_type" type="string">
  Media type filter, passed as is. 200 characters max.
</ParamField>
<ParamField body="sort_order" type="string">
  `relevance`, `date_asc` or `date_desc` (case-insensitive).
</ParamField>
<ParamField body="date_from" type="string">
  Start date, `YYYY-MM-DD`. Must be a real calendar date.
</ParamField>
<ParamField body="date_to" type="string">
  End date, `YYYY-MM-DD`, on or after `date_from`.
</ParamField>

```bash
curl https://findly.icu/api/v1/search/intelligence-search \
  -H "Authorization: Bearer fly_live_XXXX" \
  -H "Content-Type: application/json" \
  -d '{"query": "example.com", "max_results": 200, "date_from": "2024-01-01", "date_to": "2024-12-31"}'
```

### Phonebook

Every known selector for a domain. `type` decides both what you get back and the shape `query` must have.

<ParamField body="type" type="string" required>
  `email`, `domain` or `url` (case-insensitive).
</ParamField>
<ParamField body="query" type="string" required>
  Depends on `type`. Sent lowercased.
</ParamField>

| `type` | You get | `query` must look like |
| --- | --- | --- |
| `email` | Email addresses at the domain | `@example.com` |
| `domain` | Subdomains | `example.com` |
| `url` | URLs | `https://example.com` (http or https, no credentials) |

The domain must be a real domain name: IP addresses, `localhost` and non-ASCII names are refused.

```bash
curl https://findly.icu/api/v1/search/phonebook \
  -H "Authorization: Bearer fly_live_XXXX" \
  -H "Content-Type: application/json" \
  -d '{"type": "email", "query": "@example.com"}'
```

### Identity Portal

<ParamField body="query" type="string" required>
  Email address, domain or other selector. 200 characters max.
</ParamField>

```bash
curl https://findly.icu/api/v1/search/identity-portal \
  -H "Authorization: Bearer fly_live_XXXX" \
  -H "Content-Type: application/json" \
  -d '{"query": "john.doe@example.com"}'
```

### System ID

Downloads the raw file behind a result.

<ParamField body="system_id" type="string" required>
  UUID (`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`), usually `results[].system_id` from Intelligence Search or Identity Portal. Case-insensitive.
</ParamField>

### Storage ID

Downloads a raw file by storage ID.

<ParamField body="storage_id" type="string" required>
  128 or 129 hexadecimal characters. Spaces and line breaks are removed, so a wrapped copy-paste works (1,000 characters max as sent).
</ParamField>
<ParamField body="bucket" type="string" required>
  One of the exact values below.
</ParamField>

| `bucket` | | |
| --- | --- | --- |
| `leaks.private.general` | `leaks.private` | `leaks.logs` |
| `leaks.public` | `documents.public` | `web.public` |
| `pastes` | `darknet` | `dns` |
| `whois` | `usenet` | `dumpster` |

Both file modules are covered in [Raw files and text output](/guides/raw-files).

## FindLy Module

Our own module, on the breach index Find.ly ingests and documents itself. It draws from the separate **Breach Search** bucket, never from the IntelX request quota.

### Breach Search

Records for one person across our own breach index. The base request is a **single free-text value** — no options — and that covers most searches. An **advanced** form lets you combine named fields when you need to narrow to one person.

Send `query`, `fields`, or both. At least one is required.

#### Base search

<ParamField body="query" type="string" required>
  Anything that names a person — an email, a full name, a username, a phone number. 256 characters max, 3 minimum. An address is matched exactly; other text is matched across name, username, phone, company, city and more at once. Sensitive fields (IBAN, SIRET) are never searched.
</ParamField>

```bash
curl https://findly.icu/api/v1/search/breach-search \
  -H "Authorization: Bearer fly_live_XXXX" \
  -H "Content-Type: application/json" \
  -d '{"query": "jane.doe@example.com"}'
```

#### Advanced search

<ParamField body="fields" type="object">
  A map of `field: value`. Each entry is a **separate, required constraint** — the index ANDs them, so `city` + `last_name` + `first_name` narrows to the one person, where a free `query` only ranks a bag of terms. Combine it with `query` and that too must match.
</ParamField>

Accepted keys: `full_name`, `first_name`, `last_name`, `username`, `email`, `phone`, `company`, `city`, `region`. Each value is 2–256 characters. At most 10 fields per request. `iban` and `siret` are refused — they are never a search target, in any form.

```bash
curl https://findly.icu/api/v1/search/breach-search \
  -H "Authorization: Bearer fly_live_XXXX" \
  -H "Content-Type: application/json" \
  -d '{"fields": {"city": "Paris", "last_name": "Dupont", "first_name": "Jean"}}'
```

An unknown or sensitive key returns `422 invalid_input` (as `fields.<key>`) and is never billed. A blank value is dropped; if nothing is left to search, the request is refused before it costs anything.

#### What you get back

- **Up to 100 records** per search, each with the breach it came from (see the *Breach records* tab below). `total` counts up to 10,000; past that, `total_is_lower_bound` is `true`.
- There is no next page: narrow with `fields` instead.
- No `?format=txt` (`400 unsupported_format`).
- No password is ever returned, in clear or hashed. A partially shown value (an IBAN as its last four characters) is listed in `masked_fields`.
- A search that takes over 20 seconds is refunded (`502 upstream_error`). If the index runs out of its own time budget, it returns what it found with `partial: true`; an empty partial result is refunded.

<Note>
  Breach Search uses a **separate daily bucket** (Starter 100, Professional 800, Enterprise 5,000), independent of the
  IntelX request quota. See [Billing and quotas](/guides/billing-and-quotas#daily-quotas).
</Note>

<Warning>
  Results come from leaked and public data. Treat every string (`name`, `line`, `selector`, file text) as untrusted: escape it before displaying it in HTML and never execute it.
</Warning>
